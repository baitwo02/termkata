# ADR 0003：词汇来源改用 LLM API 生成

- 状态：已接受
- 日期：2026-10-07
- 决策者：用户 + AI agent

## 背景

v0.1 原计划使用固定词库（`words.json`）+ 过滤 / 不重复抽词，但"词库更新机制"（结合 GitHub 热门项目）一直没有可行方案：维护成本高、内容容易过时。用户提出：词汇直接由 LLM API 按需生成，用户手动维护“兴趣领域”列表。

## 决定

1. 词汇由 **LLM API 按需生成**（BYOK：用户自配 API key，客户端直连，无后端）。
2. 一轮练习状态机只接收“词汇已就绪”这一事实，**不感知网络与模型**；生成是独立子系统。
3. 用户**兴趣领域**由用户手动维护（增删），作为词汇生成的上下文输入；结构待定（AGENTS.md §10）。
4. 固定词库 `words.json` 不再作为 v0.1 的依赖；词库更新管线不再规划。

## 理由与替代方案

- 固定词库 + GitHub 更新管线：机制未定、维护成本高、内容易过时 → 弃。
- API 生成的成本：网络依赖、费用、隐私（提示词 / 词汇离开本机）、离线不可用、结果非确定性；收益是零维护、词汇新鲜。
- 用户数据仍全部本地：只有生成请求会发送给 API，训练数据不出本机。

## 后果

- 需要 API key 存储方案（本地文件 / 系统 keyring，待定）。
- 测试中词汇生成器必须可注入（假实现），core 单测不触网。
- 离线兜底、失败重试、模型与提示词策略列入待定项（AGENTS.md §10）。
