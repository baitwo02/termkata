# ADR 0004：核心实现语言改为 Rust

- 状态：已接受
- 日期：2026-10-08
- 决策者：用户 + AI agent

## 背景

用户目标：核心功能可无 UI 运行（CLI 是合法宿主），平台覆盖 Win / macOS / Linux / Android，未来可能接入 Flutter / 原生宿主或 Web 版。此前核心以 TypeScript 实现（`src/lib/core/round.ts`），只能被 JS/TS 宿主复用；跨语言（Flutter/Dart、原生）无法使用。

## 决定

1. 核心（状态机与领域逻辑）改为 **Rust**，位于 Cargo workspace 的 `crates/core`，**零外部依赖**。
2. 宿主持有**权威状态**；UI 只持有渲染镜像，经宿主接口（Tauri IPC / CLI 调用 / WASM 桥）读写。
3. 删除 TS 版核心与 Vitest；核心单测改用 `cargo test`。
4. Web（WASM）、Flutter（FFI）等桥接层**待真实需要时**再添加，core 本身不预埋。

## 理由与替代方案

- 保留 TS core：实现快，但无法被非 JS 宿主消费，与"CLI 可实现全部功能 + 跨平台（含 Android）"的目标冲突 → 弃。
- TS + Rust 双实现：两份逻辑必然行为漂移 → 弃。
- 现在就做 WASM/FFI 桥：当前没有非 JS 宿主，属于过度设计（YAGNI）→ 推迟。
- 选择 Rust 的直接理由：Tauri 壳本身即 Rust（桌面 + Android），core 放入 Rust 后与壳零跨语言成本；纯逻辑代码翻译成本低（前一轮的纯函数设计使其成为机械工作）。

## 后果

- 单测与 CI 以 `cargo test` 为准；`pnpm test` / Vitest 移除（UI 侧将来若需要 TS 测试再单独提案）。
- UI 迭代需要 IPC 桥：Rust 宿主持有状态，Svelte 经 Tauri 命令/事件读取并镜像渲染。
- 未来 Web / Flutter 宿主会有各自的桥接层；core 不变。
- 开发环境无需新增工具（Nix flake 已含 Rust stable）。
