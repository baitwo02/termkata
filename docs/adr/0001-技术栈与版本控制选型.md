# ADR 0001：技术栈与版本控制选型

- 状态：已接受
- 日期：2026-10-07
- 决策者：用户 + AI agent

## 背景

termkata 从零开始。需求：本地优先、跨平台桌面、功能解耦、MVP 小步交付；未来可能开源（GPL-3.0）。用户主环境为 Fedora 44 KDE。

## 决定

1. **桌面壳**：Tauri 2（Rust + 系统 WebView）。
2. **前端**：Svelte 5 + SvelteKit（SPA / adapter-static）+ TypeScript + Vite（Tauri 官方 Svelte 模板形态）。
3. **架构**：纯 Web UI + `lib/platform` 适配层，UI 不直接调用 Tauri API，为未来 Web 版留门。
4. **版本控制**：Jujutsu（jj），colocated Git 后端；GitHub 托管、Actions、PR 不受影响。
5. **许可证**：GPL-3.0-only。

## 理由与替代方案

- Electron 体积与内存开销大，对个人工具不成比例 → 弃。
- 纯 Vite + Svelte 少一层框架，但后续多视图（抽卡 / 计时 / 历史 / 设置）需要路由；SvelteKit 是 Tauri 官方 Svelte 推荐形态 → 采用。
- git 缺少内建 undo 工作流；jj 的工作区自动快照、`jj undo` / `op log` 对 AI 频繁改代码的场景恢复成本更低 → 采用 jj（Git 后端保证 GitHub 兼容）。

## 后果

- 本地构建需要 Rust toolchain 与 Linux WebKitGTK 系统依赖。
- 协作者需了解 jj 基本操作（见 `AGENTS.md` §7 / §9）。
- CI 需要三平台矩阵；发布由 tag 触发 `tauri-action`。
