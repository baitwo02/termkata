# ADR 0005：LLM 接入（provider 分层、`.env` 验证期密钥）

- 状态：已接受
- 日期：2026-10-09
- 决策者：用户 + AI agent

## 背景

ADR 0003 决定词汇来源改为 LLM API 按需生成（BYOK、客户端直连、无后端）。
本迭代落地第一个真实 provider（用户持有 DeepSeek key）。
用户要求架构按"每家一个 provider"设计（参考 pi coding agent 的模型配置：provider 与 wire 协议分离），
AGENTS.md §10 的 API 细节项就此定稿。

## 决定

1. **provider 与协议分离**（`crates/wordgen`）：
   - **厂商 = 数据**：`providers::ProviderSpec`（id / base_url / api_key_env / default_model）
   - **协议 = 代码**：`openai_chat`（OpenAI 兼容 chat completions 的传输，30s 超时，rustls）
   - **生成层**：提示词 + 输出解析（`deepseek::DeepSeekSource`），对 core 只暴露 `WordSource`
   - 本轮只实现 DeepSeek（其 API 兼容 OpenAI chat 协议）；接 Anthropic 等 = 新增协议实现 + 厂商定义，不改生成逻辑与状态机
2. **依赖**：`reqwest`（rustls，避免 OpenSSL 系统依赖）+ `serde_json`（wordgen）；`tokio`（CLI 运行时）；Tauri 侧计划用 `tauri::async_runtime`（不额外引入 tokio）。
3. **密钥（验证期）**：`.env`（从当前目录向上找最近的，已存在的环境变量优先），变量名 `DEEPSEEK_API_KEY`。
   `.env` 不提交（见 `.gitignore`），仓库保留 `.env.example`。持久化（keyring / 配置文件）留待 user 状态机迭代再定。
4. **无 key 不静默回退假实现**：CLI 启动时明确报错（退出码 1，提示 `--fake`）；
   Tauri 启动后抽取时报错（`AnySource::Unconfigured`）。`--fake` 仅供开发调试与集成测试。
5. **失败语义**：错误经 `RequestFailed` 回到就绪并显示原因，可重抽；首版不做自动重试、离线兜底、流式输出。
6. **提示词**：固定常量（wordgen），要求只输出术语；兴趣领域作为上下文留待 v0.1.1。
7. **来源装配**：`AnySource` enum（DeepSeek / Fake / Unconfigured）——
   `WordSource` 返回 `impl Future`，非对象安全，不能使用 trait object。

## 理由与替代方案

- 单一 OpenAI 兼容客户端 + 硬编码端点：接非兼容厂商（如 Anthropic messages 协议）需要改核心代码 → 弃。
- `Box<dyn WordSource>`：RPITIT 不是对象安全 → 用 enum 装配。
- 仅环境变量（不读 `.env`）：每次开发都要手动 export，易忘 → `.env` 更顺手；
  keyring 引入平台差异与额外依赖，验证期不值得。

## 后果

- `wordgen` 携带 HTTP 依赖（core 仍零依赖）。
- `.env` 是开发/验证期方案：从启动器打开 GUI（无终端环境）时密钥持久化尚未解决 → backlog。
- 模型固定 `deepseek-chat`；多模型 / 多 provider 选择 UI 未做 → backlog。
- `host::exec` 的极简执行器退居测试用途（真实宿主各有正式运行时）。
